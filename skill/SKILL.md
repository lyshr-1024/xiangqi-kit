# 象棋（Xiangqi）

## 铁律

**棋盘状态只存在于引擎里，不存在于你的记忆里。** LLM 靠文字记棋盘，
二三十步后必然记错子的位置、走出不合法的棋。因此：

- 任何走子、判断"这步能不能走"、报告局面，都必须调用 CLI，以其输出为准。
- 绝不在脑内推演"现在马应该在哪"——用 `show`。
- 绝不自己判断走法是否合法——`move` 会校验，非法会报错并 exit 1。
- 用户报的着法解析失败时，跑 `legal` 找相近的合法写法，向用户确认。
- `move` 成功后会回显规范记谱（"已走：X"），复述给用户时以它为准；
  如果它和用户的意图明显不符（用户可能笔误或记谱方向搞反），先 `undo`
  再和用户确认，不要将错就错。
- 点评局面（威胁、吃子、将军）前先跑 `show` 或 `fen` 核对，禁止基于
  记忆断言"你的马被打了"这类事实。

## CLI

入口是本目录的 `./xq`（零依赖，系统 python3 即可）。棋局存在
`~/.xiangqi/games/<name>.json`，跨会话自动续棋。

| 命令 | 作用 |
|---|---|
| `xq new [--fen FEN] [--force]` | 开新棋局（默认标准开局） |
| `xq show` | 显示棋盘与轮走方/将军/终局状态 |
| `xq move <记谱>` | 走一步，如 `xq move 炮二平五` |
| `xq ai` | 让 AI 走一步（装了 Pikafish 自动用它，远强于内置搜索） |
| `xq engine [install]` | 查看 / 安装外部引擎 Pikafish |
| `xq undo` | 悔一步棋 |
| `xq legal` | 列出当前所有合法着法 |
| `xq fen` | 输出当前局面 FEN |
| `xq svg [--out 路径]` | 导出当前局面 SVG（含上一步高亮），输出文件路径 |
| `xq history` | 显示完整棋谱 |
| `xq play [--side black]` | 全屏鼠标对弈（交互式，你跑不了；用户嫌对话下棋慢时，建议他在自己终端里跑，存档共用、可回到对话复盘） |

所有命令支持 `-n <名字>` 管理多盘棋（默认 `default`）。

## 记谱速查

- 红方用汉字数字（炮二平五），黑方用阿拉伯数字（马8进7）；解析时两者混用也能识别。
- 路数从各自右手数起；车炮兵帅进退记步数，马象士进退记到达路数。
- 同线双子用前/后：前车进三、后炮平5。

## 典型流程

**展示棋盘（优先可视化）**：走完子或用户要看局面时，跑 `xq svg` 拿到
SVG 文件路径，用 SendUserFile（display: render）发给用户，让棋盘直接
显示在侧栏。无法发文件的环境（纯终端）退回 `xq show`，把文本棋盘放
代码块里贴出。两者不必同时。

**用户想下棋**：`xq new`（已有棋局则先问是续棋还是重开），按上面的
方式展示开局棋盘，约定用户执红或黑。

**用户报一步**：`xq move <着法>` → 成功后展示新棋盘；轮到 AI 就
`xq ai`，并把 AI 的着法与棋盘一并报告。

**复盘**：`xq history` 看棋谱，`xq undo` 回退，配合 `show` 逐步讲解。

**输出里出现「棋局结束」**：向用户宣布结果（将死/困毙/三次重复判和），
不要再试图走子。
